# v1.0 紧急补丁与回滚流程

1. 确认事件级别，冻结非修复提交，在问题登记中记录负责人、影响范围和可复现条件。
2. 若存在数据损坏、供应链风险或无法启动，立即把正式 Release 标记说明更新为暂停下载，并引导使用同页的签名回滚包。
3. 从 `v1.0.0` 创建 `hotfix/1.0.x`；只合入最小修复和对应回归测试，版本递增为 `1.0.1` 等补丁号。
4. 完整运行测试、标准性能比较、发布长稳测试、洁净机安装/升级/卸载、Defender 与多引擎检查。
5. 使用生产证书和 RFC 3161 时间戳重新签名；生成新的稳定清单、SHA-256、SBOM、构建溯源和发布说明。禁止复用旧版本号或覆盖已公开资产。
6. 由另一名审核者核对标签、提交、签名指纹、资产哈希和更新清单，再发布补丁并重启 72 小时监控。

回滚不删除用户数据。若项目格式或设置迁移不可逆，补丁发布前必须提供显式迁移/恢复工具；不得建议用户手工删除配置来掩盖问题。
