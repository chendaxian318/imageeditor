# v0.5.0 UI framework decision

Date: 2026-08-04  
Decision: Continue with Tkinter through v1.0 unless a later gate fails.

## Evidence

- A 1920 × 1080 image with 100 editable vector rectangles rendered in a
  **41.3 ms median** over seven full-resolution runs.
- A 1920 × 1080 noise image with 10 alternating mosaic/blur regions rendered
  in a **118.3 ms median** over five runs.
- At a simulated 192 DPI (200%) scale, selection handles use a 16-pixel hit
  radius and real canvas create/select/move interactions passed.
- Annotation rendering is performed by the existing single background preview
  worker, while selection outlines and handles remain lightweight Canvas items.
- The existing packaging, single-instance, Windows file integration and test
  suite remain compatible without introducing a second UI runtime.

## Gate result

The measured canvas performance and high-DPI pointer interaction meet the v0.5
requirements. A PySide6 migration would add schedule, package-size and regression
risk without solving an observed release blocker, so migration is not approved
for the active roadmap.

## Reopen conditions

Treat migration as a separate 4–6 week project only if one of these conditions
is reproduced and cannot be fixed within Tkinter:

- 100 vector objects exceed 250 ms median preview render time on the supported
  minimum machine.
- Selection/move interaction falls below 30 UI updates per second for normal
  office-sized images.
- 100–200% DPI or multi-monitor movement produces unfixable hit-region or layout
  errors.
- Required screen-reader names, focus navigation or future editing components
  cannot be exposed with acceptable behaviour.

No feature development and framework migration may run in the same milestone.
