# Release compliance checklist

Complete this checklist for every release candidate. A checked box must be
supported by CI output or a durable review record.

## First-party rights

- [ ] Source-provenance gate in `source-provenance.md` is cleared.
- [ ] Approved first-party licence matches the rights holder's written grant.
- [ ] All contributor, contractor and employment IP obligations are satisfied.
- [ ] Product name, logo, icon and bundled sample assets are cleared.

## Dependency and notice audit

- [ ] Environment was created exclusively from the committed lock files.
- [ ] `pip freeze --all` matches the approved build inventory.
- [ ] PyInstaller archive/installer payload was inspected for shipped modules.
- [ ] `THIRD_PARTY_LICENSES.md` matches the exact released wheels and tools.
- [ ] Complete package-supplied licence texts are included in the distribution.
- [ ] FreeType acknowledgement remains present in distribution documentation.
- [ ] No unreviewed GPL/AGPL/copyleft component or asset was introduced.

## Build and artifact evidence

- [ ] Source commit and annotated version tag are recorded.
- [ ] CI checkout is clean before and after build.
- [ ] Tests, static checks and type checks pass before packaging.
- [ ] Build uses the pinned Python patch version and locked dependencies.
- [ ] Executable product/file version and publisher identity were inspected.
- [ ] Installer install, upgrade and uninstall were tested on Windows x64.
- [ ] SHA-256 checksums and artifact byte sizes were generated by CI.
- [ ] Signing certificate, timestamp server and signature verification are
      recorded without exposing private keys.

## Functional and performance evidence

- [ ] Existing regression/characterisation tests pass.
- [ ] `benchmarks/run_benchmarks.py --profile smoke` completes.
- [ ] Startup, large-image open, folder switching and batch metrics were
      compared with the previous accepted baseline.
- [ ] No unexplained material performance regression was accepted.

## Publication decision

- [ ] Release notes describe known limitations and incompatible changes.
- [ ] Privacy, telemetry, update and network behaviour are documented.
- [ ] Final approver and approval time are recorded.
- [ ] Published files exactly match the signed/checksummed CI artifacts.
