# 四模式图片软件开发计划报告

> 文档版本：1.69
> 制定日期：2026-08-06
> 当前软件版本：1.1.3
> 目标产品版本：2.0
> 目标平台：Windows 10 22H2 / Windows 11 x64
> 产品语言：仅简体中文
> 推荐技术路线：模块化单体 + 可插拔 AI 能力

## 1. 执行摘要

软件最终划分为四个一级模块：

1. **看图模式**：打开、浏览、检查和管理已有图片。
2. **转图模式**：裁切、旋转、尺寸、格式、压缩、元数据和批量转换。
3. **改图模式**：高清放大、修改图片文字、去背景，以及现有调色、标注、修复类能力。
4. **生图模式**：通过文字或参考图生成新的图片资产。

当前项目不是从零开始。现有 1.1.3 代码已经具备成熟的看图、格式转换、批处理、非破坏编辑、标注、项目恢复和安全导出能力。开发重点应是：

- 将现有功能重新归入四个清晰工作区，而不是继续堆在一个主窗口。
- 建立“原功能零丢失”迁移台账，任何现有功能都必须有明确入口。
- 复用现有解码、渲染、导出和批处理内核，避免重复实现。
- 为高清、改文字、去背景和生图建立统一但隔离的 AI 任务平台。
- 保证看图与转图始终可以完全离线使用；AI 未配置、失败或崩溃时不影响基础软件。

按“2 名开发者 + 兼职产品/UI + 兼职 QA”估算，四模式稳定版约需 **24～28 周**。单人全职开发约需 **40～48 周**。建议按版本逐步发布，不等待全部 AI 功能完成后才验证市场。

- M5 第一条闭环已完成：真实源像素按 2×/4× 使用 LANCZOS 本地高清，保留 RGBA，执行、取消和入库均离开 Tk 主线程；结果沿用源 AssetId、以源 RevisionId 为父修订，可在改图画布并排对比、放弃候选，或带真实身份进入转图队列。
- M5 第二条闭环已完成：离线确定性去背景不再只平均四个角，而是从整圈边框受限采样，以量化主色家族排除贴边主体，并按背景自身色差自适应容差；主体覆盖整条边及两个角、背景缓慢渐变时仍可生成稳定 Alpha。自动蒙版继续与原图 Alpha 相乘，受控半透明主体不会被强行变成不透明；背景容差、边缘羽化、统一任务取消、托管子修订、结果放弃、对比和转图交接流程保持不变。该基线仍不能替代真实复杂毛发、玻璃、烟雾等生产级分割。
- M5 第三条闭环已完成：用户可在画布框选并校正原文字区域，离线 Provider 采样周边像素修复背景，再以微软雅黑、等线、宋体或黑体重新排版；字号、颜色、左/中/右对齐和旋转可调，参数具备独立撤销/重做历史并可再次生成。打开其他图片会取消旧任务并清空文字区域，避免跨图片串用结果。OCR 内容识别和复杂纹理修复仍待真实 Provider。
- M5 第四条文字区域建议闭环已完成：新增完全离线的局部对比度、连通行与旋转校正分析服务，在后台给出最多 5 个归一化文字行候选；检测器先以10°步长覆盖 -90°～+90°，再从最多4个互异高置信方向执行±5°范围的1°精修，普通印刷体候选携带精修旋转角度，选中后自动同步到替换排版，用户仍可在画布拖动校正。精确竖排图像本身不能判断阅读方向，因此同时保留 +90°/-90°候选供用户切换。平坦图片安全返回空结果，检测失败自动回退手工框选，换图会作废旧检测，图片不会上传。受控单平面梯形透视扩展见第二十一条，空间分离双平面见第二十四条，受控弧形普通印刷体扩展见第二十六条；仍不声称支持重叠/遮挡平面或复杂艺术字。
- M5 第五条边缘细化闭环已完成：透明结果可使用保留主体和删除背景两种画笔，画布以绿/红遮罩显示有序笔划；笔划使用严格的归一化坐标契约，离线 Provider 在真实 RGBA 像素上更新 Alpha。每次应用均以当前去背景结果为父修订创建新的透明 PNG，上一修订不被覆盖，结果可继续细化或带真实身份发送到转图；换图会清空未应用笔划，避免跨图串用。
- M5 第六条稳定性闭环已完成：改图任务成功记录可跨重启读取，提交或执行中断会恢复为“状态未知”并在界面明确提示，系统不会自动重放；取消请求优先于晚到的成功回包，避免已取消任务意外生成候选。智能结果入库前强制校验任务类型、成功候选数量、请求编号、Provider、源 RevisionId、操作类型和高清倍率；损坏、超限、错误 MIME、伪造血缘与跨资源父修订均原子失败，不留下数据库行或托管 Blob。
- M5 第七条独立质量门禁已完成：新增可命令行运行的 smoke/standard 门禁，直接消费离线 Provider 的真实 PNG，而非依赖 UI 状态。standard 使用 512×384 样本、白色/绿色/深色三种背景且每项重复 3 次；2×/4× 输出尺寸和 RGBA 均正确，Alpha 回采 MAE 为 0，像素可复现；三种普通背景的前景召回率与背景去除率均为 100%。主体贴边渐变与半透明样本的前景 Alpha MAE 均为 0、背景去除率均为 100%。保留/删除画笔分别得到 255/0 Alpha 且血缘正确；横排改文字区域变化率为 43.0132%、区域外像素保持率 100%，新文字红色像素 5,971 个。竖排替换探针得到 3,026 个红色文字像素、纵向长宽比 9.46875、区域外像素保持率 100%。透视替换探针得到 3,179 个红色文字像素、四边形外像素保持率 100%、P95 为 45.015 ms；受控透视样本稳定检出四边形，候选区域重叠率 100%、左右尺度差 4.7448%、专项 P95 为 414.320 ms。0°、17°、+30°、-30°、58°、80°、-83°和90°八个文字区域样本全部检出，最大角度误差为1°，最低候选重叠率 95.9002%，含透视样本的检测总体 P95 为 603.419 ms，仍低于1,000 ms门槛；微软雅黑与宋体字体推荐 Top-1 全命中；居中高对比、贴边渐变、透明 Alpha、分离双主体、异色相接/可见重叠、同色细颈相接和同色中等宽接触七个智能选区样本覆盖率均为 100%、最低 IoU 为 82.8439%、结果可复现；后三类场景分别稳定返回安全合并候选及 2 个互斥颜色/形状分离候选。原始样本见 `docs/release/m5-smart-edit-smoke.json`。
- M5 第八条本地文字内容识别基线已完成：改图“替换图片文字”可在自动检测或手工校正区域后执行本机识别；旋转或竖排普通印刷体先按同步角度反向校正为横向裁切，受控透视四角先重采样为正面矩形，受控单行二次基线弧形文字会在 OCR 前执行几何校直。Windows 10/11 优先调用系统 `Windows.Media.Ocr` 与用户语言包，无需另装程序；系统后端不可用、失败或无文字时自动尝试 Tesseract，后者优先简体中文加英文语言包并解析逐行 TSV 可信度。Windows 系统返回有效空结果时，会在同一个 30 秒总预算内执行最高 3×、最长边 2,400 px、总像素不超过 8,000 万的灰度自适应对比度增强重试；界面明确标记增强与几何校正路径。两种后端共用独立临时目录且全程不上传图片；系统 API 不提供词级可信度时界面显示“系统未提供可信度”，不伪造分数。所有后端均失败时保留手工输入，换图会使晚到结果失效。该能力是普通印刷体和受控渐变、图案、低对比、旋转、透视及弧形几何校正本地基线，不声称已经达到真实照片复杂背景、重叠/遮挡多平面或艺术字生产级 OCR 质量；弧形校直专项见第二十七条。
- M5 第九条背景替换闭环已完成：透明结果可在同一改图面板中选择纯色或本地自定义图片背景；自定义图片按居中覆盖适配尺寸，透明区域以用户底色兜底。合成离开 Tk 主线程并原子写入不透明 PNG，以当前透明 RevisionId 为父修订、沿用原 AssetId，记录背景类型、颜色、文件名与内容 SHA-256；多次尝试从同一透明结果生成互不覆盖的分支，任一结果可直接发送到转图。损坏、超限、无透明 Alpha、非法颜色、待执行取消与换图晚到结果均失败关闭。M5 standard 门禁对纯色和自定义背景各重复 3 次，背景与主体像素、完全不透明 Alpha、确定性和背景哈希全部通过，本轮 P95 分别为 9.279/10.849 ms。

## 2. 产品定位与原则

### 2.1 产品定位

定位为一款中文、轻量、Windows 本地优先的图片工作台：

- 普通用户可以把它作为默认看图软件。
- 办公与内容创作者可以快速裁切、改尺寸、转格式和批量处理。
- 非专业设计用户可以完成高清、改字、抠图等智能改图。
- 有生成需求的用户可以在同一资源库中生成、筛选、再编辑和导出图片。

### 2.2 六项产品原则

1. **四模式职责清晰**：每个功能只有一个主要归属，跨模式通过“发送到……”交接。
2. **原功能零丢失**：界面重构不能以“简洁”为理由删除或隐藏原有能力。
3. **原图默认不覆盖**：所有转换、AI 编辑和生成结果默认创建新文件或新修订。
4. **本地基础能力不依赖 AI**：看图和转图不联网、不登录也能完整使用。
5. **AI 调用透明**：上传内容、供应商、预计费用和失败状态必须对用户可见。
6. **渐进式重构**：继续使用现有 Python、Tkinter、Pillow 和 NumPy，先拆职责，不立即重写技术栈。

## 4. 四模块产品定义

### 4.1 看图模式

#### 模块目标

以最少干扰快速打开、浏览、检查和管理图片，不修改图片像素。

#### 核心流程

打开图片或文件夹 → 浏览/缩放/检查 → 管理文件 → 发送到转图或改图

#### MVP

- 打开单图、多图、文件夹、拖放和剪贴板图片。
- 左侧缩略图库、搜索、自然排序、上一张/下一张。
- 适应窗口、实际尺寸、连续缩放和平移。
- 全屏、沉浸模式、幻灯片。
- 图片属性、基础 EXIF、格式、尺寸和文件大小。
- 动画图片自动播放与基础播放控制。
- 明确的“转图”和“改图”交接按钮。

#### V1

- 暂停、逐帧、进度、倍速等动画控制。
- 两张不同图片并排比较。
- 收藏、评分、标签和筛选。
- 最近目录、跨目录搜索和相似图片发现。

#### 验收标准

- 24 MP JPEG 首次可见预览 P95 不超过 1.8 秒。
- 已预取图片切换 P95 不超过 300 毫秒。
- 500 张目录滚动和导航无明显主线程卡顿。
- 损坏图片只影响自身，不中断浏览序列。
- 100 张连续浏览后内存不持续单调增长。
- 打开、切图、缩放、全屏和模式交接均有键盘路径。

### 4.2 转图模式

#### 模块目标

将一张或多张输入图片按确定规则转换成目标文件。按照本项目产品定义，**裁切、格式和尺寸的主要入口归转图模式**。

#### 核心流程

添加文件/文件夹 → 配置转换配方 → 预览输出 → 检查冲突 → 执行 → 查看结果或失败项

#### MVP

- 单张和批量输入。
- 可视裁切、固定比例裁切和居中裁切。
- 左右旋转、水平/垂直翻转。
- 宽高、百分比、最长边和常用尺寸。
- JPEG、PNG、WebP、AVIF、BMP、TIFF 转换。
- 质量、目标 KB、输出目录和文件名前后缀。
- 元数据保留/清理和透明通道处理。
- 同名策略、原子写入、进度、取消和逐项错误隔离。
- 配方保存、导入和导出。

#### V1

- 多步骤可视化转换配方。
- 一次输出多个尺寸或格式变体。
- WebP 无损、PNG 色深/调色板、TIFF 压缩等格式高级参数。
- GIF/APNG/WebP 动画统一转换入口。
- HEIF/HEIC 可选输出。
- 任务恢复、失败重试、再次运行、CSV/JSON 日志。
- 输入样张、预计体积和预计耗时。

#### V2

- 监视文件夹和拖放式快捷转换。
- 命令行转换接口。
- 配方分享、任务历史和性能调度。
- RAW 显影转换、多页 TIFF 和更多专业格式。

#### 验收标准

- 1,000 文件任务中单项失败不阻塞其余任务。
- 峰值内存不超过用户设置的预算。
- 未明确选择覆盖时绝不覆盖源文件。
- 输出采用原子写入，中断后不留下伪成功文件。
- 目标 KB 在可压缩样本上的偏差控制在 ±10%。
- 点击取消后 1 秒内停止派发新任务，并保存可恢复状态。
- 所有成功输出都能由本软件重新解码。

### 4.3 改图模式

#### 模块目标

改变图片的视觉内容或质量。按照本项目产品定义，**高清、改文字和去背景归改图模式**，即使底层由 AI Provider 执行，也不改变产品入口归属。

#### 现有基础工具

- 光线、色彩、曲线、色阶、锐化和降噪。
- 标注、马赛克、模糊、遮挡和水印对象。
- 透视、画布扩展、历史、撤销/重做和项目保存。
- 编辑前后比较。

#### 智能改图 MVP

**高清：**

- 2 倍和 4 倍高清放大。
- 大图分块处理、进度、取消和失败重试。
- 原图/结果局部放大对比。
- 输出保存为新的图片修订。

**去背景：**

- 人像与常见商品图的主体分离。
- 透明背景、纯色背景或自定义背景替换。
- 边缘羽化、保留/删除画笔和结果预览。
- 默认导出透明 PNG，其他格式交给转图模式处理。

**改文字 1.0：**

- OCR 检测文字区域。
- 用户选择并校正文字区域。
- 擦除原文字并修复背景。
- 输入新文字，调整字体、字号、颜色、对齐和旋转。
- 允许用户手工微调，首版不承诺自动完全匹配复杂艺术字体。

#### V1

- 复杂纹理生成式修复、扩图和更自然的物体擦除边缘。
- 更稳定的头发/透明物体边缘。
- 普通本机字体相似度推荐、受控单平面/空间分离双平面透视排版、受控单行弧形普通印刷体检测、OCR 前几何校直、手动弧度排版，以及水平普通印刷体纯色/描边/偏移投影/线性渐变/单色扩散发光分类、参数估计与可编辑替换已有基线；平滑渐变/低频纹理、周期性高频纹理/正交亮度结构及受控多尺度照片式随机纹理/密集枝状边缘背景的纯色/发光分析也已进入门禁。继续扩展艺术字体、重叠/遮挡多平面场景文字、真实照片弧形识别语料、真实照片语义内容/复杂自然对象/强遮挡、多层/非均匀发光、纹理/三维/非线性变形高级艺术字和多段落排版。
- 多主体候选、启发式像素蒙版预览、加入/移出画笔精修、隔离修复、异色相接/可见重叠颜色分离及同色可见中等宽接触形状分离已有受控基线；继续扩展生产级语义分割、同色深度重叠和遮挡对象恢复。
- AI 操作历史、前后对比和结果版本树。

#### V2

- 图层、蒙版、混合模式和对象树。
- 多文档工作区。
- 更完善的 RAW、高位深与局部画笔工作流。
- 可组合的智能编辑配方。

#### 验收标准

- 任何 AI 结果都创建新的 AssetRevision，不覆盖原图。
- 高清结果尺寸严格符合 2 倍/4 倍设置，处理失败可恢复。
- 去背景结果保留合法 Alpha 通道，并提供手工边缘修正。
- 改文字流程允许撤销、重做和再次编辑文字对象。
- 连续 100 次确定性编辑、撤销和历史跳转无状态漂移。
- 项目保存重开后，确定性命令和已物化 AI 结果保持一致。
- 滑块操作 100 毫秒内出现首个视觉反馈。

### 4.4 生图模式

#### 模块目标

从文字或参考图片创造新的视觉资产。生图结果先进入共享资源库，再发送到看图、改图或转图。

#### MVP

- 文本提示词。
- 宽高比、分辨率档和生成数量。
- 明确选择模型或供应商。
- 任务队列、进度、取消、失败重试。
- 候选网格、放大查看、收藏、仅看收藏与安全移除；移除不破坏受管修订和任务追溯。
- 保存提示词、模型、种子、生成时间和来源。
- 一键发送到改图或转图。
- 每次上传参考图或产生费用前明确确认。

#### V1

- 最多四张参考图共同生图。
- 每张参考图独立设置内容、风格、构图角色与强度。
- 负面提示词、固定种子、风格预设和候选变体。
- 预计费用、额度和供应商状态。
- 局部重绘、扩图和蒙版输入。

#### V2

- 更细粒度的结构/姿态控制。
- 批量变体和提示词模板。
- 本地模型包与云端模型切换。
- 版本化生成工作流。

#### 验收标准

- 点击生成后 200 毫秒内显示明确任务状态。
- 网络失败、限流、内容策略拒绝和供应商异常均有可恢复说明。
- 重试使用幂等键，不能静默重复扣费。
- 100% 生成结果记录模型、参数、种子和来源。
- 参考图未经本次明确确认不得上传。
- 生成结果经过格式、尺寸、MIME 和安全解码检查后才能导入资源库。

## 5. 功能归属与交接规则

| 功能 | 主要归属 | 交接规则 |
| --- | --- | --- |
| 打开、浏览、缩放、全屏 | 看图 | 不写入编辑历史 |
| 裁切、旋转、翻转、尺寸 | 转图 | 改图可以调用快捷裁切，但进入同一共享几何服务 |
| 格式、质量、目标 KB、元数据 | 转图 | 其他模块的“导出”统一调用转图引擎 |
| 批量处理、重命名、输出冲突 | 转图 | 不在改图中重复实现 |
| 调色、曲线、标注、历史 | 改图 | 使用现有非破坏 Document 与 Timeline |
| 高清、改文字、去背景 | 改图 | 底层可调用 AI Provider，结果物化为图片修订 |
| 文生图、参考图生图、候选变体 | 生图 | 结果进入资源库后再交给其他模块 |
| 水印 | 转图/改图 | 转图是批处理配方；改图是可编辑对象 |
| 对比 | 看图/改图 | 看图比较不同文件；改图比较编辑前后 |
| 项目、设置、诊断、更新 | 全局 | 四个模式共享，不重复建设 |

### 原功能零丢失门禁

- 建立机器可读的 Feature Registry，记录功能 ID、中文名称、所属模式、入口、快捷键和回调。
- README 与用户手册中的现有功能必须全部映射到一个模式或全局功能。
- 每个功能至少有一个可见入口，不能只剩隐藏菜单或快捷键。
- UI 自动化测试必须验证四模式切换后所有 P0/P1 功能仍可到达。
- 每次移动入口时保留原回调和行为测试，禁止同时重写业务逻辑。

### 7.3 共享数据模型

**AssetRecord**

- 资源 ID、外部路径或托管文件。
- SHA-256、尺寸、格式、色彩和元数据。
- 来源类型：本地打开、转换输出、改图结果、生图结果。

**AssetRevision**

- 父修订 ID。
- 结果文件哈希与位置。
- 操作类型与参数摘要。
- AI Provider、模型、版本、请求 ID、费用和时间。

**TransformRecipe**

- 有序本地操作列表。
- 导出格式、质量、命名、冲突和元数据策略。

**EditDocument**

- 继续使用现有确定性 EditTimeline。
- AI 结果以 AssetRevision 引用进入项目，不在撤销时重新调用云端。

**JobRecord**

- 模块、状态、进度、重试次数、输入、输出、错误、费用和时间。

### 7.4 AI Provider 设计

至少定义两个能力协议：

- ContentEditProvider：高清、去背景、文字区域识别/修复等改图任务。
- GenerationProvider：文生图、参考图生图、变体和局部生成。

Provider 必须声明：

- Provider ID、适配器版本和协议版本。
- 是否本地运行、是否上传图片。
- 支持的任务、尺寸、参考图、种子和蒙版能力。
- 认证方式、费用估算、区域和文件限制。
- 取消、重试和幂等能力。

推荐分三步：

1. 先实现 Mock Provider，覆盖成功、超时、限流、拒绝、取消和损坏结果。
2. 接入一个真实 Provider 完成端到端验证。
3. 再支持独立子进程 Provider；本地模型也作为 Provider，不侵入业务模块。

不要在第一阶段开放任意 Python 插件直接加载。外部 Provider 应通过版本化 JSON-RPC 或 JSON Lines 子进程协议隔离，避免依赖冲突和任意代码执行风险。

## 10. 测试与发布门禁

### 10.1 功能测试

- Feature Registry 与 UI 入口一一对应。
- 四模式切换和跨模式 Asset/Revision 传递。
- 单张与批量转换使用同一配方语义。
- 改图项目保存、恢复、撤销和 AI 修订引用。
- 生图候选发送到看图、改图和转图。

### 10.2 图像测试

- 现有确定性操作继续使用黄金图和像素容差。
- 8 种 EXIF Orientation、ICC、透明度和动画样本。
- 高清固定本地模型可做感知相似度和尺寸测试。
- 云端 AI 不要求像素一致，只验证格式、尺寸、来源、状态和安全边界。

### 10.3 Provider 契约测试

每个 Provider 运行同一套测试：

- 参数验证。
- 成功、超时、限流、拒绝和取消。
- 重试幂等。
- 损坏、超大、错误 MIME 和恶意响应。
- 费用与用量记录。
- 插件崩溃隔离。

### 10.4 性能与稳定性

- 启动、24/50 MP 图片、500 图目录和连续切图。
- 1,000 文件转换、失败隔离、取消和内存预算已有自动化门禁；后续继续扩展到大尺寸混合格式样本。
- AI 下载、生成、取消时 UI 保持响应。
- 100%/125%/150%/200% DPI。
- Windows 10/11、安装版/便携版、升级和回滚。

### 10.5 安全与隐私

- 基础模式绝不因 AI 组件缺失而联网或失败。
- 凭据存入 Windows Credential Manager 或 DPAPI，不进入设置、项目和日志。
- 上传参考图前逐次确认供应商、内容和预计费用。
- 下载结果先进入临时目录，通过安全解码后原子导入。
- 提示词和生成历史默认只保存在本机，并支持一键清除。
- 上线 AI 前将隐私承诺更新为“基础功能永不上传；AI 任务逐次明确授权”。

## 11. 主要风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| main_window.py 继续膨胀 | 四模式互相耦合 | 用 ModeHost 和门面逐步迁移，禁止一次性重写 |
| AI 模型体积与显卡兼容 | 安装包过大、部分机器不可用 | 模型可选下载，本地模型独立子进程，云端作为可选 Provider |
| 改文字质量不稳定 | 用户预期落差最大 | 将 OCR、擦除、字体、排版拆阶段，首版明确支持手工校正 |
| 去背景边缘质量 | 头发和透明物体失败 | 先聚焦人像/商品图，提供保留/删除画笔 |
| 云端费用与重复提交 | 用户损失和投诉 | 费用确认、幂等键、提交状态不明时禁止自动换供应商 |
| AI 不可复现 | 撤销或重开结果变化 | 结果物化为 AssetRevision，保存输入哈希和完整来源 |
| Provider API 变化 | 功能中断 | 能力协商、适配器契约测试和版本化协议 |
| Tk 大型蒙版性能不足 | 改图交互卡顿 | 缩放代理图、分块刷新；达到性能阈值后再评估 UI 栈 |
| 既有功能再次“消失” | 用户信任下降 | Feature Registry、可见入口测试、零丢失发布门禁 |
| 内容与模型许可 | 无法商业发布 | 每个 Provider/模型维护许可、版本和用途清单 |

## 12. 需要确认的产品决策

以下决策不阻塞 M0～M2，但应在 AI 平台开发前确认：

1. AI 首版采用云端、本地还是混合方案。推荐混合架构，首版只接一个真实 Provider。
2. 高清与去背景是否必须完全离线。
3. “改文字”的首版验收标准：普通印刷体，还是包含艺术字、透视和复杂纹理。
4. **已决策并完成离线基线**：生图首版包含最多四张逐项参考图；真实云端上传仍需逐次明确确认。
5. 是否接受 AI 功能独立下载模型或产生第三方费用。
6. 实际团队人数与目标发布日期。

## 14. 最终建议

近期不要继续把所有能力塞进同一个“图片编辑器”页面，也不要为了四模式立即更换 UI 技术栈。最稳妥的路线是：

> 先用四模式外壳重新组织现有成熟能力，完成看图与转图；再建设独立 AI 平台，依次交付高清、去背景、改文字；最后接入生图，并将所有生成结果纳入同一资源与修订体系。

这样既能保住当前软件已有的大量功能，也能让后续 AI 能力在隐私、费用、稳定性和可扩展性上保持可控。
